# What the laptop's workers are RUNNING. Not what a tree is checked out at.
#
# The compute node's timer reads this with
#     git show origin/main:plans/DECLARED-REVISION.txt
# every few minutes, and syncs itself to it. It refuses rather than guesses:
# a sha absent from the clone, a sha that is not an ancestor of origin/develop,
# a dirty deploy slot, or an install that leaves a sibling wrong all leave the
# worker DOWN. A silent wrong consumer is worse than no consumer.
#
# WHY "RUNNING" AND NOT "CHECKED OUT". On 2026-08-30 a branch was checked out
# in this machine's deploy tree while a twelve arm sweep was live. The workers
# had loaded their code hours earlier and never reloaded, so every arm computed
# identically, but two of them recorded a revision no process had ever held,
# and six batches of a third were refused and dead-lettered by the guard that
# noticed. The tree and the running code are two different quantities. This
# file names the second.
#
# Every sibling package is derived from this commit's own poetry.lock, so there
# is no second list to disagree with. Add an override line only when knowingly
# ahead of the lock, one per package, first match wins.
#
# WHEN NOT TO MOVE IT. Not while a campaign is live. The node's guard defers
# while a batch is in flight and then pins to the new sha, so it will REFUSE
# the remaining batches of the campaign it was already serving. That is the
# guard working: no prediction set ends up holding rows written by two code
# versions, which is the failure the 2026-08-30 sweep produced. But the refusal
# is invisible from the server, where it looks like a queue with a consumer
# that is not consuming, and a failure that is safe and invisible is the worst
# kind to diagnose. It already cost an afternoon once, on the sibling pin.
#
# So the check before editing this file is on the SERVER and not on the node:
#     no job in QUEUED or RUNNING, and no prediction set being written.
# The node's guard covers its own half of the risk. It cannot see the queue.
#
# Update this when the WORKERS move, not when the tree does.
